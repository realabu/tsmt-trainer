# UX / Design Mode

## Purpose

UX / Design mode translates product direction into usable experience structure.

It turns product principles and decisions into journeys, flows, screen responsibilities, wireframes, interaction models, and design principles.

## Scope

Use this mode for:

- user journeys
- task flows
- screen responsibilities
- wireframes
- interaction models
- design principles
- progress and feedback models
- physical/digital hybrid experience thinking

Do not use this mode to finalize implementation details or create technical architecture.

## Rules

- Do not become pixel-perfect too early.
- Prioritize clarity.
- Prioritize progress understanding.
- Prioritize child-friendly interaction.
- Prioritize low cognitive load.
- Preserve the low-screen product philosophy.
- Support physical/digital hybrid thinking.
- Separate journey, screen architecture, wireframe, and visual design layers.
- Do not add new product features unless discovery has established them.

## Design Layers

### Journey

The user path across time, motivation, context, and goals.

### Screen Architecture

The responsibility of each screen or surface.

### Wireframe

The layout and information structure needed to support the journey.

### Visual Design

The final visual treatment, hierarchy, style, and polish.

These layers should stay distinct until the product direction is stable enough to combine them.

## Collaboration Behavior

In this mode, ChatGPT or Codex should translate product intent into experience structure.

The assistant should name tradeoffs, keep the experience understandable, and avoid premature precision. It should protect the user from turning every product idea into a new screen.

## Expected Outputs

Useful outputs may include:

- journey maps
- flow outlines
- screen responsibility notes
- wireframe descriptions
- interaction principles
- state and feedback models
- design decision records

## How To Use This

Start UX threads with the thread start template and set `Mode` to `UX / Design`.

Before moving to Engineering mode, identify which UX decisions are committed and which remain exploratory.
